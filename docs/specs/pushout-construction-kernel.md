# Pushout Construction Kernel

## Purpose

Turn the explicit pushout from a metadata-only report into a real finite
**colimit (pushout) construction** that materializes the merged structure as a
reviewable candidate, and that detects the genuine gluing-axiom obstructions a
metadata report cannot see.

This closes a claim-vs-reality gap. Today
`higher_graphen_structure::morphism::explicit_pushout_candidate` reports which
elements *would* be identified, but `ExplicitPushoutReport::candidate_space_shell`
returns an **empty** `Space` (id and name only). No merged cells, incidences, or
complex are ever constructed, and no check verifies that the identification is
well defined. "Local-to-global gluing" is therefore a label, not a computed
result.

## Scope

In scope for this cycle (`higher-graphen-structure` only):

- A pure, deterministic finite pushout constructor over a cospan
  `B <-left- A -right-> C` that materializes merged `Cell`s, `Incidence`s, a
  `Complex`, and a populated candidate `Space`.
- The well-definedness (gluing-axiom) obstructions listed below, in addition to
  the two obstructions that already exist.
- Concrete quotient-loss records (replace the current boilerplate strings).
- Tests proving construction correctness, every obstruction case, determinism,
  and JSON round-trip.

Explicit non-goals for this cycle (do **not** implement now):

- No change to `higher_graphen_reasoning::gluing::attempt_gluing` or to the core
  `GluingResult`/`CorrespondenceCell` types. Rewiring the correspondence-level
  classifier onto this constructor touches core serialization, schemas, and the
  CLI and will be a separate reviewed cycle. The correspondence path keeps its
  current behavior.
- No general N-ary colimit. Binary pushout over one apex only.
- No functors, natural transformations, or pullback changes.
- No new crate dependencies.

## Mathematical Definition

Given a cospan in the category of finite cell structures:

```text
        left          right
   B  <-------  A  ------->  C
```

`A` is the apex (the overlap). `left: A -> B` and `right: A -> C` are the two
`Morphism`s; their `cell_mapping` / `relation_mapping` send each apex element to
its image in `B` and `C`.

The pushout `P = B +_A C` is the quotient of the disjoint union `B ⊔ C` by the
equivalence relation generated by:

```text
left(a) ~ right(a)   for every apex element a present in both legs
```

Concretely:

- Elements of `B` and `C` that are not identified are carried into `P`
  unchanged (re-homed to the candidate space).
- Each `~`-class becomes a single merged element in `P`.
- Incidences are carried into `P` with endpoints relabeled through the
  identification; incidences induced by the same apex relation are merged.

The construction is only well defined when each merged class is internally
consistent. The obstructions below are exactly the conditions under which it is
not.

## Inputs

The constructor must operate on explicit finite element collections so it stays
pure and unit-testable (no store dependency required). Recommended shape (names
may be adjusted to crate conventions; semantics are fixed):

```text
PushoutInputs {
    left: &Morphism,                 // A -> B
    right: &Morphism,                // A -> C
    candidate_space_id: Id,
    candidate_space_name: String,
    complex_type: ComplexType,       // default CellComplex
    left_cells: &[Cell],             // cells of B referenced by left.cell_mapping targets (and B-private cells to carry)
    right_cells: &[Cell],            // cells of C
    left_incidences: &[Incidence],   // incidences of B
    right_incidences: &[Incidence],  // incidences of C
}
```

The apex `A` does not need its own element collection: the identification pairs
are read from the shared keys of `left.cell_mapping` / `right.cell_mapping`
(and likewise for `relation_mapping`), which already encode `left(a)` and
`right(a)`. Reuse the existing `helpers::pushout_groups` to obtain
`identified_*_groups` and `unmatched_*_source_ids`.

## Identification Algorithm

1. Build a union-find over the disjoint union of target cells, keyed by
   `(Side, Id)` where `Side ∈ {Left, Right}` (ids may collide across `B` and
   `C`; keep them distinct by side).
2. For each `IdentifiedSourceGroup` from `pushout_groups(cell_mapping)`, union
   `(Left, left_target_id)` with `(Right, right_target_id)`.
3. Each union-find class is one merged cell. Assign a **deterministic** canonical
   merged id (document the rule; e.g. derive from the sorted list of member
   `(Side, Id)`), with `space_id = candidate_space_id`.
4. Carry private (unmatched) cells of `B` and `C` into `P` as their own
   singleton classes.
5. Repeat the union-find for relations using `pushout_groups(relation_mapping)`.

Merged cell attributes (per class):

- `dimension`: must be equal across all members. Unequal ⇒ blocking
  `IncompatibleIdentification`.
- `cell_type`: must be equal across all members. Unequal ⇒ blocking
  `IncompatibleIdentification`.
- `label`: if members disagree, choose a deterministic canonical value and
  record a concrete quotient loss for each dropped value (non-blocking).
- `boundary`, `coboundary`, `context_ids`: union across members, with every
  member id remapped through the cell identification, then sorted and
  deduplicated.
- `provenance`: drop to `None` on merged classes with >1 member and record a
  quotient loss (do not fabricate provenance); keep it for singletons.

Merged incidence attributes:

- Remap `from_cell_id` and `to_cell_id` through the cell identification to
  canonical ids.
- Two incidences in the same relation `~`-class must, after remapping, agree on
  `(from_cell_id, to_cell_id, relation_type, orientation)`. Disagreement ⇒
  blocking `RelationEndpointConflict`.
- Private incidences are carried over with remapped endpoints. After remapping,
  deduplicate incidences that become identical on
  `(from, to, relation_type, orientation)`; record a quotient loss when a
  distinct `weight` or `provenance` is dropped by dedup.

## Obstruction Families

Stable, `snake_case`-serialized codes. The first two already exist; keep them.

| Code | Severity | Meaning |
| --- | --- | --- |
| `incompatible_source_space` | blocking | `left.source_space_id != right.source_space_id`; not a cospan. |
| `pushout_incomplete` | blocking | An apex element is mapped by one leg but not the other (`unmatched_*` non-empty). |
| `incompatible_identification` | blocking | A merged class contains cells (or relations) with conflicting `dimension`/`cell_type` (cells) or relation_type/orientation that cannot be one element. |
| `relation_endpoint_conflict` | blocking | An identified relation class maps to incidences whose remapped endpoints disagree. |
| `ambiguous_identification` | review | The generated equivalence merges two or more originally-distinct same-side elements (the cospan collapses more than one element of `B`, or of `C`, into one). The pushout is still well defined but lossy; flag for review. |

Rules:

- If **any blocking** obstruction is present, do **not** materialize an accepted
  merged structure. Return a blocked outcome carrying the obstructions and the
  report; emit no `cells`/`incidences`/`complex` as if they were valid. (You may
  still return the partial identification report for diagnostics, but it must be
  clearly non-constructed.)
- If only `ambiguous_identification` (review) obstructions are present, do
  materialize the merged structure but set `review_status` so it is a candidate
  requiring review, and record the collapses as quotient losses.
- With no obstructions, materialize the merged structure as an unreviewed
  candidate.

## Output

```text
PushoutOutcome =
  | Constructed { construction: PushoutConstruction, report: ExplicitPushoutReport }
  | Blocked { report: ExplicitPushoutReport }

PushoutConstruction {
    space: Space,            // populated: cell_ids, incidence_ids, complex_ids, context_ids
    complex: Complex,        // merged complex: cell_ids, incidence_ids, max_dimension, complex_type
    cells: Vec<Cell>,        // materialized merged + carried cells (space_id = candidate_space_id)
    incidences: Vec<Incidence>,
    review_status: ReviewStatus, // Unreviewed or Candidate — NEVER Accepted
}
```

- `max_dimension` = max `dimension` over merged cells (0 if empty).
- The populated `Space.cell_ids` / `incidence_ids` / `complex_ids` /
  `context_ids` must match the materialized elements exactly.
- `ExplicitPushoutReport.quotient_losses` must be **concrete** (which attribute
  of which source element was dropped/overridden), not the current two
  boilerplate strings.
- Replace the empty `candidate_space_shell`: either remove it (preferred, if it
  becomes unused) or make it delegate to the real construction. Do not keep an
  empty-shell path that silently looks like a built space.

## Safety / Review Rules (must hold)

- The constructed structure is always a reviewable candidate. `review_status`
  must never be `Accepted` from this function.
- No silent promotion: blocking obstructions ⇒ no materialized accepted
  structure.
- All information loss is explicit in `quotient_losses` (label overrides,
  dropped provenance, dedup-dropped weights, ambiguous collapses).
- Output identifier ordering is deterministic (sort all `Vec<Id>` and element
  lists by `Id`); two runs on equal input produce byte-identical JSON.

## Minimal Acceptance Contract

The kernel is done only when it has:

- A bounded input record and a structured output record.
- At least one fully-satisfied case: a clean cospan that materializes the
  correct merged complex (assert exact merged cells, incidences, identified
  class, `max_dimension`, populated `Space` membership).
- At least one test per obstruction code above (5 total), asserting the code is
  produced and (for blocking) that no accepted structure is materialized.
- A determinism test (same input → identical serialized output; identifier
  ordering stable).
- A JSON round-trip test for the new report/outcome records
  (`serde_json` to-string then from-str equals original).
- `cargo fmt`, `cargo clippy --workspace --all-targets` clean (no new warnings;
  the workspace lints set `missing_docs = warn`, `unsafe_code = forbid`, and
  `clippy::all = warn` — add `///` docs on all new public items).
- No new crate dependencies; no `unwrap`/`expect`/`panic!` on the non-test path.
